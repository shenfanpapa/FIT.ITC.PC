# FIT.ITC.PC 教室设备管理系统

面向小组内部共用的教室设备布局与巡检网站，支持桌面浏览器和手机浏览器。

界面加入由当前主题配色驱动的高反差斜切海报式动效。动画仅在首次进入页面时播放，使用约 2 秒的 GPU 合成动画；按钮、设备和弹窗保留轻量微交互。系统启用“减少动态效果”时会自动关闭动画。

日期切换会立即重新计算当日巡检分组；所有布局、分组、设备和巡检修改都会立即进入串行上传队列。历史页面、异常窗口和手机版菜单均可导出异常履历 CSV，内容同时包含未修复与已修复记录。

每日巡检进度由服务器共享记录：同一天重复打开不会前进；如果中间一天或多天完全没人打开网站，下一次打开只前进一列，因此不会跳过本来应该检查的列。多台设备同时保存发生版本冲突时，客户端会自动拉取最新记录、合并并重试。

正确设备坐标保存在不可变的 `defaults/roomcheck.default.json` 中，并带有坐标版本标记。新部署会直接使用这套默认值；检测到 Railway 持久卷中的旧坐标版本时，会自动迁移到正确布局，并按设备编号、标签和分组名称尽量保留已有巡检与异常履历。

## 已包含的数据

- 8 个教室
- 900 台设备
- 62 个巡检分组
- 已导入提供的正确设备坐标、既有巡检记录与异常备注

## 本地运行

1. 安装 Node.js 18 或更高版本。
2. 在项目目录运行 `npm install`。
3. 运行 `npm start`。
4. 打开 `http://localhost:3000`。

项目不再显示登录页面。建议只把网站部署在小组可访问的网络或受保护的 Railway 域名中。

## Railway 数据持久化

请在 Railway 为服务挂载持久卷，并把环境变量 `DATA_DIR` 指向挂载目录，例如 `/data`。不设置时，数据保存在项目的 `data` 目录。

## 数据安全

- 保存采用临时文件替换，避免产生半写入 JSON。
- 每次保存前会保留 `roomcheck.json.bak`。
- 多个终端同时编辑时会检测版本冲突，不再静默覆盖。
- 设置面板中可创建和恢复人工快照。

## 检查

运行 `npm run check` 可检查服务端语法及教室、设备、分组之间的数据完整性。
